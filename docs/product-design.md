# 观微元小程序设计规范

## 产品方向

围绕「发现好问题 → 记录思考 → 获得反馈」组织数学学习社区。参考成熟产品的交互模式，结合观微元的课程、每周一题和师生交流场景落地。

| 参考产品 | 借鉴的模式 | 在观微元的应用 |
| --- | --- | --- |
| 小红书 | 内容优先、双列卡片、中心发布入口 | 发现与社区信息流、主题筛选、写作编辑器 |
| B站 | 内容分区与分类浏览 | 学习入口、课程资料目录、专题归类 |
| 多邻国 | 明确的下一步与轻量成长反馈 | 每周挑战、实际作答和批改统计、温和提示 |

以上为设计模式参考，不代表实时热度排名。保留观微元自己的品牌、插画与数学学习语境。

## 信息架构

- **发现**：本周挑战、真实学习概况、笔记和资料推荐。
- **学习**：个人学习记录、每周一题、课程资料、探索实验室。
- **发布**：随手记录问题、推导与经验；这是操作入口，不是独立常驻栏目。
- **社区**：按提问、打卡、分享、指导分类，支持搜索。
- **我的**：学习档案、个人资料、教师认证和退出登录。

四个常驻栏目使用微信原生 Tab 页面，中心发布入口打开编辑器。资料目录、阅读页、编辑资料属于二级页面，保留返回路径。

## 视觉规范

颜色以 `frontend/miniprogram/styles/tokens.wxss` 为统一来源：米白背景 `#f6f4eb`、暖白卡片 `#fffdf7`、青绿主色 `#4b8067`、深绿文字 `#2e3e33`，淡紫仅用于 Logo 关联的辅助区域。避免大面积深蓝。

主标题约 38–44rpx，正文约 26–31rpx，辅助说明一般 22–24rpx。正文与功能提示保持清晰对比；较淡的颜色用于装饰线条。常用卡片圆角约 22–28rpx，页面水平留白约 30rpx。用层级、间距、轻边框组织页面，减少大面积重阴影。

`assets/covers/` 中的四张数学线条插画用于内容封面和实验室预告；用户原始 Logo 保存在 `assets/logo-original.jpg`。

## 交互约定

- 加载、空白、失败分别呈现；失败提供重试入口。
- 统计使用后端真实记录，不展示虚构连续打卡或能力评分。
- 示例帖子明确标记「示例内容」，未完成资料与 AI 功能明确标记「筹备中」。
- 草稿按当前用户隔离，离开编辑器保存，成功发布后清除；避免重复提交。
- 登录、认证错误尽量在表单内反馈。认证面板打开时隐藏底栏，关闭时恢复。
- 新用户统一按学生注册；教师从个人中心认证，教师与管理员保留各自工作入口。
- 阅读页正文可复制，日期兼容 Flask RFC 日期与 iOS 小程序环境。
